# Online player invitations

Presence is independent of matchmaking, statistics and rendering. Main-app signed-in Google and Guest UIDs each use `playerPresence/{uid}` with only `v: 1` and a server `lastSeen` timestamp. No names, ratings or solve data are copied. Anonymous medal-worker sessions do not join presence.

Visible online tabs elect one heartbeat owner per UID/origin using Web Locks. Other tabs wait without Firestore traffic. Hiding, going offline, signing out, pagehide and disposal stop the subscription/heartbeat and release the lock. Pageshow restores participation. No tab deletes the shared UID document: another tab/device might still be online. Presence expires after 90 seconds. Older browsers without Web Locks may subscribe in each tab, but still count one UID and Rules reject updates less than 25 seconds apart. Multiple devices have the same limitation.

The leader writes every 30 seconds and subscribes to at most 50 recently active UID documents. The moving 90-second query window refreshes every 90 seconds independently of heartbeats; a lightweight one-second local expiry check removes stale observations. A two-document existence query cannot reliably track each arrival, so this bounded active-user window replaces it. No unbounded user/profile query or index is added. Stale documents remain but are outside the query window and are reused on return.

Approximate per visible signed-in user/hour: unchanged 120 heartbeat writes. With N steady visible users (N <= 50), listener refreshes read about 40N documents/hour and live heartbeat updates can read about 120N/hour per observer, roughly 160N combined, excluding reconnects/churn/Rules charges. For N=5 this is roughly 800 reads/hour per observer, not a measured bill or strict ceiling. Empty queries have minimum charges. Refreshing every 90 rather than 30 seconds cuts refresh reads by two-thirds. Project-wide presence reads grow approximately quadratically with active observers; monitor Spark's shared quota as traffic grows. Web Locks remove same-browser duplicate subscriptions, not cross-device traffic.

Each previously unseen active UID arms an invitation, including arrivals while other users remain online. A per-controller UID/last-seen cache suppresses heartbeats, duplicate tabs and reconnects within five minutes of the last heartbeat. Query removal/reinsertion alone does not mean a new arrival. Expired cache entries are pruned. Initial existing users cause one invitation, and multiple arrivals during unsafe gameplay are coalesced into one pending invitation. A new arrival while the toast is visible resets its six-second timeout. Notifications are per tab session, not a server-global delivery guarantee; a different tab taking over may show its own initial invitation. CTA opens Random Battle without starting a search. Existing Google-login requirements remain unchanged.

New/invalid/blocked local BOT preferences default OFF. Previously explicitly saved `true` remains ON and saved `false` remains OFF; old unsaved defaults become OFF. Matchmaking and Elo are unchanged.

Presence is approximate, not proof of an available opponent. Sudden disconnects may remain online for up to 90 seconds; clock skew, connectivity, suspension and quota failures can delay/suppress invitations. The 50-document window is sized for current low traffic: more than 50 simultaneous users can make arrival detection incomplete. No disconnect write is relied on. Rules permit signed-in lists of at most 50, owner-only server-timestamp writes at least 25 seconds apart, exact schema and no deletes. They cannot prove genuine activity. The adapter and UI remain separated for a future authoritative presence provider.
