# Online player invitations

Presence is independent of matchmaking, statistics and rendering. Main-app signed-in Google and Guest UIDs each use `playerPresence/{uid}` with only `v: 1` and a server `lastSeen` timestamp. No names, ratings or solve data are copied. Anonymous medal-worker sessions do not join presence.

Visible online tabs elect one heartbeat owner per UID/origin using Web Locks. Other tabs wait without Firestore traffic. Hiding, going offline, signing out, pagehide and disposal stop the subscription/heartbeat and release the lock. Pageshow restores participation. No tab deletes the shared UID document: another tab/device might still be online. Presence expires after 90 seconds. Older browsers without Web Locks may subscribe in each tab, but still count one UID and Rules reject updates less than 25 seconds apart. Multiple devices have the same limitation.

The leader writes every 30 seconds and subscribes to only the two most recently active UID documents. The moving 90-second query window refreshes every heartbeat; a lightweight one-second local expiry check removes stale observations. Two documents suffice to detect another UID even when self is returned. No unbounded user/profile query or index is added. Stale presence documents remain but are outside the query window and are reused on return.

Approximate per visible signed-in user/hour: 120 heartbeat writes, up to 240 initial document reads from listener refreshes, plus live result-change reads (including self heartbeats, other heartbeats and query-result churn). Empty queries have the normal minimum query charge. Reconnection and active-user churn can increase reads; this is not a fixed upper bound. One visible Google/Guest tab continuously open for 24 hours can cause 2,880 writes. Scale against the project's shared Spark quota; no paid plan or Functions are enabled. Web Locks remove same-browser duplicate subscriptions, not cross-device traffic.

Only transitions from no other user to at least one other user arm an invitation. It is consumed when shown, dismissed or clicked, and hides after six seconds. Unsafe gameplay/modals defer pending invitations and immediately hide visible ones. Notifications are per tab session, not a server-global delivery guarantee. A different tab taking over may show its own first invitation. CTA opens the existing Random Battle controls without starting a search. Existing Google-login requirements for Ranked remain unchanged.

New/invalid/blocked local BOT preferences default OFF. Previously explicitly saved `true` remains ON and saved `false` remains OFF; old unsaved defaults become OFF. Matchmaking and Elo are unchanged.

Presence is approximate, not proof of an available opponent. Sudden disconnects may remain online for up to 90 seconds; clock skew, lost connectivity, browser suspension and quota failures can delay/suppress invitations. No disconnect write is relied on. Firestore Rules allow signed-in bounded lists (maximum two), owner-only server-timestamp writes with a 25-second minimum interval, exact schema, no deletes. They cannot prove that a client is genuinely active. The data adapter and UI are separated for a future authoritative presence provider.
